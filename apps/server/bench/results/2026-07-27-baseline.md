## Conditions

- **Target:** `http://127.0.0.1:8080` — the `komika-server-1` container's published port.
  Bypasses the cloudflared tunnel and Cloudflare's edge, so these are **origin** numbers.
- **Host:** 4 vCPU / 23 GiB Oracle VPS, shared with the unrelated `clubsite-*` and
  `torchy-*` stacks. `clubsite-worker` was measured at **53% CPU** throughout.
- **Dev noise present:** VS Code, 4 vite dev servers and a debug `komika_server` build
  were resident; swap was 3.5/4 GiB used. **These numbers are therefore slightly
  pessimistic** vs a clean prod box.
- **Server build:** the deployed container (18 h uptime), *not* the working tree.
- **Traffic:** live production traffic was also being served during the runs.
- Windows are 2 s warmup (discarded) + 8 s measured per step unless noted.

## Field-cost isolation on `discovery`

Mean of 5 sequential requests each, varying only the selection set. **This is the
decisive experiment** — it rules out the field resolvers as the primary cost.

| Selection | Mean latency |
|---|---|
| `id title` only | **61.3 ms** |
| all flat scalars (no sub-objects) | 59.0 ms |
| + `rating` (already batched) | 55.4 ms |
| + `scan` | 55.9 ms |
| + `detectedAt` — full fragment | **71.2 ms** |
| `id title detectedAt` only | 69.2 ms |

Selecting nothing but `id` and `title` still costs **61 of the 71 ms**. ~86% of the cost
is the base `discovery` resolver (`graphql/mod.rs:2490`), not field selection. The
`detectedAt` per-row N+1 (`graphql/mod.rs:359`) is real but secondary at ~10–14 ms.

Variance across the three middle rows (55.4–59.0 ms) is within run-to-run noise on a
box also serving live traffic; treat them as equal.

## Schema drift discovered

The deployed server **rejects** `sort`, `hasChapters`, `types`, `status` and
`contentRating` on `search`, and has no `BrowseSort` enum:

```
{"errors":[{"message":"Unknown type \"BrowseSort\""},
           {"message":"Unknown argument \"sort\" on field \"search\" of type \"QueryRoot\""},
           {"message":"Unknown argument \"hasChapters\" on field \"search\" of type \"QueryRoot\""}]}
```

`packages/api/src/operations.ts` already ships all of them, and its own comment notes
Browse has **no fallback path**. **The server must deploy before the reader.**

Live surface confirmed working: `query`, `page`, `genres`, `includeNsfw`
(`search(query:"",page:1)` → `total: 13584`).
